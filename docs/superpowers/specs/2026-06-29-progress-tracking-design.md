# 设计文档：开发进度追踪体系

**日期**：2026-06-29
**状态**：已批准

---

## 背景

项目可能在多台电脑、多种 AI 工具之间切换开发。需要一套文档结构，让任何人（或 AI 工具）拿到仓库后，不需要询问就能知道：

1. 项目现在在哪个阶段
2. 上次完成了什么
3. 下一步具体做什么

同时，进度记录应能直接复用为发布说明，减少重复整理工作。

---

## 决策

**方案 B（进度单独文档）+ 按里程碑粒度记录。**

- `PLAN.md` 保持不变，作为规划基准（里程碑定义、功能边界、技术选型）
- `PROGRESS.md` 独立记录实际进度，按里程碑倒序（最新在上）
- `README.md` 顶部放两行"当前状态"快照，指向 PROGRESS.md

---

## 文档结构

```
docs/
├── PLAN.md          # 规划基准（不随进度改动）
├── PROGRESS.md      # 进度日志（每完成一个里程碑追加一条）
└── ARCHITECTURE.md  # 架构决策
README.md            # 顶部有当前状态快照
```

---

## PROGRESS.md 条目格式

```markdown
## [M0] 项目骨架 + i18n 基建

**状态**：✅ 完成 / 🚧 进行中 / ⏳ 未开始
**完成日期**：YYYY-MM-DD（进行中则填开始日期）
**对应 git tag**：v0.1.0（完成后打 tag）

### 完成内容
- 具体做了什么（bullet，可直接用作发布说明）

### 当前停在
> 上次工作结束时停留的具体位置，精确到文件/功能点。
> 换电脑或工具时，从这里接续。

### 下一步
1. 第一件要做的事（具体可执行）
2. 第二件
3. ...

### 备注
遗留问题、临时决策、需要留意的坑。
```

---

## README 快照格式

在 README.md 顶部（项目描述之前）插入：

```markdown
## 当前状态

🚧 **M0 · 项目骨架**（进行中）— 详见 [开发进度](docs/PROGRESS.md)

**下一步**：Xcode 下载完成后，创建多平台工程 + WordClipKit Package
```

---

## 规范约定

- 每个里程碑完成后，在 PROGRESS.md **顶部**追加新条目（倒序，最新在上）
- 完成里程碑时打 git tag（`v0.1.0` 对应 M0，`v0.2.0` 对应 M1，以此类推）
- "当前停在"字段**必填**：哪怕里程碑完成，也要写"已完成，下个里程碑是 M1"
- 发布 App 版本时，从对应里程碑的"完成内容"中裁取发布说明
- PLAN.md 里程碑的 checkbox **不勾选**，进度全部在 PROGRESS.md 维护，两文件职责分离
